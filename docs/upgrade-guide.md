# 强化图鉴

入口：[强化图鉴](../upgrades.html)，也可从主菜单进入。

覆盖 18 项普攻强化、9 项 E 强化、9 项 Q 强化及 4 项通用强化。流派和类型筛选后，可搜索名称或效果。每项仅展示一段短说明和一至三项关键数值；支持竞速层数、强化前后、暂停、重播与半速。手机目录横向滚动，所有文本禁止选中。

数值与动画共同使用 `initialBuild → applyUpgrade → compileBuild`，以竞速模式的初始构筑单独获取所选强化，未选择的模块保持初始状态。通用施法加速列出三流派间隔，动画使用火球。图鉴不模拟无尽成长或多项组合。

动画复用真实 `Player`、`EnemySystem`、`SpellRunner`、`SchoolSkill` 和 `UltimateSpell`。演示敌人最多八只、无攻击、固定生命，按效果安排站位；灼烧和碎冰使用一个低生命目标触发真实死亡派生效果。Q 每轮演示预先充满。通用生命/护盾使用一次 30 点伤害，护盾演示保留完整十秒恢复等待；移速使用固定时间往返。没有改动战斗伤害、冷却或成长公式。

一个 Phaser 实例、一个场景和一套运行器；每 8.5–16.5 秒重置演示，切换与重播销毁上一轮敌人、弹丸、区域和短暂效果，共享纹理保留。新增一张 64×64 静态地格缓存，背景圆环与线条只在初始化绘制。对象上限及寿命沿用游戏：火球最多 64、冰矛 48、冰棘 12、短暂闪电 40、雷印每目标一个、E 最多 16 张图像（冰扇区域最多 16 张）、Q 最多 40 张图像和一个寒域；火区最多 18。页面不增加逐帧 DOM 更新，状态文字最多每 200 ms 检查。失焦/隐藏停止游戏及渲染循环，继续需明确点击；尺寸未变不重复调整画布，关闭解除监听并回收场景。

## 验证

- 类型检查、生产构建以及图鉴专用测试通过。40 项全部竞速层数与共享编译器一致，包含多发/追袭减伤等取舍。
- 开发运行检查覆盖 80 种基础/满层演示，真实施法及十次冰域重播通过；回收后场景根对象为 6、缓存纹理为 129，目标/弹丸/Q 效果/火区归零。
- 仓库全量 `npm test` 存在 11 个既有失败：旧数值/层数预期和 Node strip-only 不支持参数属性；在未修改的 HEAD 临时副本中复现相同失败。本次新增两项测试通过，不修改这些无关断言。

- 实际目录数量为火焰/冰霜/闪电各 12 项、通用 4 项；搜索、多重火球四层数值（9 枚、每枚 13 伤害）、强化前后、半速与文本不可选中通过。手机选中条目后保留目录横向滚动位置。
- 五次暂停/继续、模拟窗口失焦与缓存页面隐藏均停止循环，暂停等待期间活动时间不前进；重播不累计对象。
- 1280×720、390×844、740×390 检查布局，两个手机尺寸无横向页面溢出。小范围通用演示镜头拉近，法术镜头按固定目标站位适配，强化前后使用相同取景。
- 生产预览通过“主菜单 → 强化图鉴 → 主菜单”往返、手机条目切换；生产无诊断数据或开发验证控件，控制台未见错误。
- 三分钟活动时间连续巡检覆盖 40 项，峰值根对象 107、弹丸 17、Q 视觉效果 22；回收后根对象 6、纹理 129，战斗对象归零。原始记录：[持续运行](upgrade-guide-stress.json)。该检查关注对象上限与回收，不是 GPU 或内存快照。

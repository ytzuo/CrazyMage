# 游戏启动页（2026-10-03）

[游戏首页](../index.html)现在直接展示完整启动页，把竞速/无尽、男/女法师、火焰/冰霜/闪电以及[敌人图鉴](../bestiary.html)集中在一起。左侧大模型与三张流派预览复用实际角色身体、靴子和法杖缓存；形象切换更新六张预览图片和大模型，不创建第二个 Phaser 实例。男/女使用相同战斗规则。

选择模式、形象或流派只更新本局配置与预览，点击“开始试验”才调用原 chooseSchool，生成第一波六个敌人。开始前战斗时间为零、没有敌人，游戏和渲染循环休眠；重复点击开始只生效一次。战斗保持全屏，启动页不再遮挡战斗 HUD。顶栏重开、暂停菜单“返回启动页”以及死亡后的重开均重新清理本局并回到启动页。

启动页按所选模式显示流派最好成绩。模式、形象与流派仅保存为当前标签页的 sessionStorage 偏好，重新加载或图鉴往返可以保留；不保存战斗进度。存储受限或内容无效时使用默认配置，不阻止开始。原 localStorage 成绩规则不变。

桌面展示左右两栏，手机纵向展示并保留底部开始按钮；小屏和横屏可在启动页内滚动，战斗本身没有页面滚动。Tab 在启动页可用按钮与链接之间循环，图片准备前开始按钮禁用。失焦与隐藏暂停预览动画，焦点恢复仅恢复预览；已经发生的战斗失焦暂停仍需要显式继续。

没有新增战斗对象、贴图、网页计时器或逐帧界面更新。复用既有单场景、纹理缓存、暂停/失焦休眠和相同尺寸不重复调整画布的路径；预览地址仍按男女分别缓存一次。新增事件由原 Picker 的 AbortController 在热更新销毁时解绑。

## 验证

开发流程入口为 [launcher.html](../tests/launcher.html)，采样原始数据见 [launcher-performance.json](launcher-performance.json)。

- 两模式 × 两形象 × 三流派共 12 组启动与重开通过；选择不提前开局，重复开始不增加 runId，第一波为六个敌人。各次开局场景对象均为 30，重开清掉上一局并休眠。
- 五次暂停/继续、失焦后显式恢复、旧移动输入清除、暂停菜单返回启动页、重新加载保留配置和相同预览图片地址通过。
- 浏览器模拟 390×844、740×390，启动容器无横向溢出；手机开始进入全屏战斗，重开与图鉴往返保留女法师/冰霜选择。视口测试后恢复 1280×720。
- 生产预览核对无尽/女法师/闪电开局、暂停与返回启动页；竞速/女法师/冰霜的图鉴往返保留配置。十次 Tab 可遍历模式、形象、流派、开始按钮与两个链接。未出现控制台错误，生产没有战斗诊断属性。
- 类型检查与生产构建通过。既有整体界面检查适配显式开始按钮；该旧检查的完整升级与大招流程不属于本次验收，未重跑其完整战斗。

## 可比短采样

本机 macOS、Codex 内置浏览器 Chrome 154、DPR 2、预热后的 Vite 开发服务；固定 1280×720 iframe，每行 120 个渲染帧，改动前后各三轮启动后静止、向右移动和连续施法。其余 Phaser 场景暂停；未单独量化其他标签页的 CSS 动画调度成本。使用既有 PRE_RENDER 到 POST_RENDER 指标，只测渲染提交的 JavaScript 时间，不含场景更新和 GPU。加载准备时间包含 iframe 导航与 20 ms 轮询，不能当作真实冷启动时间。

下表为三轮中位数，单位 ms：

| 场景 | 原流程渲染 CPU | 新启动页渲染 CPU | 原流程帧间隔 P95 | 新启动页帧间隔 P95 |
| --- | ---: | ---: | ---: | ---: |
| 启动后静止 | 0.20 | 0.14 | 9.2 | 8.8 |
| 连续移动 | 0.18 | 0.13 | 9.1 | 8.7 |
| 连续施法 | 0.20 | 0.13 | 8.8 | 8.7 |

启动后静止场景的 iframe 准备时间中位数由 145.8 ms 变为 163.3 ms，包含上述导航、初始化与轮询误差，不作因果归因。

这一范围内没有观察到渲染耗时明显增加；绝对值很小，不据此宣称性能提升。未进行无缓存启动、完整一局、GPU/堆快照、真机或输入为粗指针的摇杆操作测量。本次没有新增持续生成或战斗资源机制，不做新的三分钟战斗压力结论。

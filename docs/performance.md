# 启动卡顿检查

本文记录本次调查。后续编码和验证要求见 [性能保障指南](performance-guide.md)。

## 确认的问题

1. 地面包含 30 × 23 = 690 块地砖，均保存在一个 Phaser Graphics 对象中。Graphics 的 WebGL 渲染器逐帧遍历绘图命令，填充路径时重新进行三角剖分；静态场景并不会自动缓存为图片。圆角地砖的填充和描边因此带来大量重复运算。
2. 原来的暂停只跳过角色和火球更新，游戏渲染循环仍在运行。暂停及失焦的试玩页也可能继续消耗渲染资源。
3. ResizeObserver 原先不判断尺寸是否真的改变，就调用画布调整。

源码依据：项目中的 `ArenaScene.ts`，以及安装的 Phaser 3.90 源码 `GraphicsWebGLRenderer.js`、`MultiPipeline.js`、`TimeStep.js`。首次框架解析、显卡初始化或其他页面的负载也可能影响开局，但本次没有单独测量这些因素，不能认定它们是实际原因。

## 已实施的改动

- 用 400 × 400 的重复地砖纹理覆盖竞技场；只生成一次 25 块地砖的图案，不再逐帧绘制 690 块地砖的路径。
- 法阵和三种装饰也缓存为小纹理，并在场景重新创建时复用。
- 暂停及失焦时暂停整个游戏并停止动画帧循环，继续时恢复；浏览器内检查暂停后的 loop.running 为 false，继续后为 true。
- 尺寸相同时不重复调整画布。
- 保持铺满窗口、无介绍文字以及原有移动和火球规则。

## 优化后的采样

浏览器视窗 1280 × 720，启动后的前 120 帧：

| 指标 | 结果 |
| --- | --- |
| 平均每帧渲染 CPU 耗时 | 0.34 毫秒 |
| 前 20 帧平均渲染 CPU 耗时 | 0.54 毫秒 |
| 平均帧间隔 | 8.28 毫秒 |
| 95% 分位帧间隔 | 8.90 毫秒 |

这是同一次浏览器运行的短时采样，不包含框架下载/解析时间、GPU 完成时间或稳定性长期测试。本次未取得可比的优化前采样，因此不宣称具体提升倍数。

类型检查和生产构建通过。浏览器中检查了火球、摇杆移动、暂停停止循环与继续恢复，未发现运行错误。
